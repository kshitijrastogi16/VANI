# VANI refinement notes

This is a working refinement of the supplied VANI ZIP, not a claim that the application is production-certified. The original uploaded ZIP was left untouched; changes are confined to this copy.

## Main changes

### Query understanding and validation
- Added a structured LLM query planner in `rag/query_planner.py` for intent, parameters, retrieval-query cleanup, language, and clarification state.
- Validates planner output locally before handing it to the application. Canonical Kanda names are resolved against SQLite; unsupported entities do not become made-up database identifiers.
- Retains deterministic fast paths for exact citations and recognized counts. Counts are computed from local data, not generated by the LLM.
- Adds query-phrase tests for common count wording, aliases, invalid Sarga identifiers, malformed planner responses, and language selection.

### Retrieval relevance
- Corrected FTS5 BM25 score normalization. SQLite FTS5 returns negative BM25 values where more-negative scores are more relevant; the former clipping formula collapsed them to the same score and destroyed ranking information.
- Restricts entity/alias expansion to single-entity-style requests. Multi-concept topical queries retain their content terms instead of expanding into broad character aliases that can dominate ranking.
- Sets `ENTITY_BOOST_FOR_GENERAL=false` in `.env.example`; turn it on only after measuring its effect on a representative dataset.
- Adds hybrid retrieval regression tests for Rama's exile and Kaikeyi's demands.

### Grounding, language, and provenance
- Adds English/Hindi/Hinglish response-language selection and localized deterministic count templates.
- Preserves trusted template citations and filters model-generated citations against the retrieved allowed IDs.
- Adds response provenance fields and a UI panel that identifies the route, dataset/tables, source IDs, retrieval method, and whether the LLM was used for planning/answer/context summary.
- Improves BYOK validation and UI gating. The supplied key is held in browser page memory, checked by the server, and sent as a request header. No key is deliberately persisted in browser storage or logged by the new validation path.

### Data and evaluation
- Expanded the integrity test so grouped verse IDs are expanded and checked against per-Sarga metadata; this verifies 19,951 individual source verses despite 18,136 searchable SQLite rows.
- Added `tools/evaluate_retrieval.py` and five hand-curated queries with expected verse IDs in `tests/data/rag_eval_cases.json`.

## Verification performed in this environment

- `python -m pytest -q`: **39 passed**.
- Python bytecode compilation for the modified application, router, planner, retriever, synthesizer, search modules, and evaluator passed.
- `node --check web/static/js/app.js` passed.
- `python tools/evaluate_retrieval.py --k 5`: on the current five-case lexical smoke set, Mean Recall@5 = **0.933**, MRR@5 = **0.767**.
- Manual retrieval/pipeline smoke checks using the supplied SQLite corpus showed relevant Ayodhya Kanda passages for Rama's exile, and the deterministic Sarga 2 Ayodhya Kanda answer of 54 verses. A dependency-shimmed smoke check was used because this environment does not contain all production runtime packages.
- A scan of source/config files found no obvious hardcoded Groq-style API key or private-key marker and no local `.env` file in this working copy.

## Important limitations / next work

- The lexical benchmark has only five curated English queries. Its metrics are a smoke baseline, not robust evidence of production-grade retrieval. Expand it with independently reviewed queries, relevant-passage annotations, paraphrases, Hindi/Hinglish, ambiguous/no-answer cases, and multiple topic families.
- A live Groq request and full FastAPI server startup were not verified here. The runtime dependencies `groq`, `faiss-cpu`, `sentence-transformers`, and `slowapi` are declared in `requirements.txt` but not all were installed in this environment; network access for installation was unavailable.
- Vector retrieval/reranking behavior and the BYOK flow must be checked on the target Windows environment with the actual dependency versions and a valid user-supplied Groq key.
- Provenance is an audit trail of pipeline operations and source IDs; it is not by itself a mathematical proof that every generated statement is entailed by the cited text. Production rollout should add claim-level citation/entailment evaluation and a wider adversarial test set.
- No commit, push, or deployment was performed.
